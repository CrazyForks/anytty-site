## 写作顺序

遵循用户约定：先规划大模块，再规划各模块的子模块，最后逐篇编写文章。

1. 确定大模块的读者、目标和内容边界。
2. 按模块展开子目录，为每篇文章明确用户问题、前置条件、适用客户端和完成结果。
3. 盘点现有文章，决定保留、拆分、合并或更新，并核实功能与发布状态。
4. 按用户上手路径编写和验证正文，再补充进阶指南与参考。
5. 同步中英文目录、链接和版本信息，检查后再接入正式导航。

## 组织原则

- 共享概念和能力集中解释；App、Web、CLI、TUI 分别提供操作入口。
- 客户端类型与连接方式分开：使用 Web 不等于使用 Cloud，使用 App 也不默认需要 Cloud。
- 快速开始围绕一次成功体验；操作指南围绕具体任务；参考页承载完整命令和参数。
- 场景指南串联已有操作文章，不重复维护安装、配对和权限说明。
- CLI 是命令与自动化入口，TUI 是交互工作台，分别组织文档。
- 源码存在、测试可用和公开发布分别核实；不把某一端的能力泛化到所有端。
- 对关闭客户端、断线、停止 daemon、主机重启和进程退出分别说明，不笼统承诺任务永不丢失。

## 首页阅读入口

- 第一次使用：认识产品 → 选择客户端 → 安装 → 完成第一个终端任务。
- 手机或平板接管：App → 添加设备与配对 → 打开已有终端。
- 浏览器访问：Web → 选择本地 Web 或 Cloud Web → 完成首次访问。
- 终端工作台：TUI → 导航与面板 → 管理多个终端。
- 命令与 AI 工具：CLI 与自动化 → 管理任务 → 查看结果和人工接管。

## 编写与验收

- 第一轮优先贯通入门、连接、第一个终端以及四类客户端的最小路径。
- 第二轮补充文件、场景、Cloud 和日常维护。
- 第三轮完善安全解释、排障与完整参考；前两轮涉及的必要权限说明和常见失败处理应随文提供。
- 每篇文章记录核验的版本、平台、功能入口和来源；命令、默认值及截图与该版本保持一致。
- 优先依据对应版本的公开源码、CLI 帮助、实际客户端和公开服务说明，不直接复制内部工程文档。
- 站点 README 与客户端 README 已存在版本及移动端分发信息差异，迁移时逐项核实，不能把任一旧文档直接当作当前事实。
- 公开内容不包含私有云实现、内部部署信息或凭据；开源客户端代码仍归 `anytty/`，云实现仍归 `anytty-cloud/`。
- 正式导航变更后运行站点检查与构建，并核对中英文链接、旧地址和各端阅读入口。

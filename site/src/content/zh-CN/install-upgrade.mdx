# 安装、升级与卸载

当前 `v0.0.1-beta.0` Release 提供 macOS、Linux、Windows 和 Android 构建。桌面端包含同一个 `anytty` 可执行文件，既是 CLI，也是 daemon 和 TUI 的入口。

## 桌面平台支持

| 平台 | 架构 | 安装方式 |
| --- | --- | --- |
| macOS | x64、ARM64 | 安装脚本或 Release 压缩包 |
| Linux | x64、ARM64 | 安装脚本或 Release 压缩包 |
| Windows | x64、ARM64 | PowerShell 脚本或 Release 压缩包 |

安装脚本从 GitHub Releases 下载匹配的归档并校验 `SHA256SUMS`。Beta 阶段的 Homebrew、npm 和 WinGet 包仍在准备中，请以 [GitHub Releases](https://github.com/anytty/anytty/releases) 为准。

## macOS 与 Linux

默认安装到 `~/.local/bin`：

```sh
curl -fsSL https://raw.githubusercontent.com/anytty/anytty/main/install.sh | sh
```

安装指定版本或目录：

```sh
curl -fsSL https://raw.githubusercontent.com/anytty/anytty/main/install.sh | \
  sh -s -- --version v0.0.1-beta.0 --bin-dir "$HOME/bin"
```

确认目标目录位于 `PATH`，然后检查版本：

```sh
anytty --version
anytty daemon doctor
```

## Windows PowerShell

```powershell
Invoke-WebRequest https://raw.githubusercontent.com/anytty/anytty/main/install.ps1 -OutFile install.ps1
.\install.ps1
```

脚本默认安装到 `%LOCALAPPDATA%\Programs\AnyTTY\bin` 并更新当前用户的 `PATH`。不希望修改 `PATH` 时使用：

```powershell
.\install.ps1 -NoModifyPath
```

重新打开 PowerShell，再执行：

```powershell
anytty --version
anytty daemon doctor
```

## Android 与 iOS

Android Beta APK 可从 Release 页面下载。当前 APK 未签名，仅适合体验和评估；安装前应核对发布标签与校验值，不要从第三方镜像获取。

iOS 客户端源码已经存在，最低支持 iOS 15，但当前没有公开安装包。Apple App Store 与 Google Play 的上架状态以落地页和 Release 说明为准。需要开发构建时，请阅读公开仓库中的 iOS 和 Android 构建说明。

## 首次启动

启动当前用户的后台服务并打开 TUI：

```sh
anytty daemon start
anytty daemon status
anytty
```

如果 `daemon start` 失败，先运行 `anytty daemon doctor`，再用 `anytty daemon logs` 查看日志。不要把未脱敏的日志直接发到公开 issue。

## 升级

升级前先阅读 [Releases](https://github.com/anytty/anytty/releases) 和[变更记录](https://github.com/anytty/anytty/blob/main/docs/zh-CN/CHANGELOG.md)。Beta 阶段不承诺旧配置、协议或数据格式一定可迁移。

推荐顺序：

1. 用 `anytty config paths` 记录当前配置、日志和历史目录。
2. 备份自己修改过的 `tui-v3.yaml` 与 `endpoints.yaml`，不要复制或公开 credential store。
3. 让重要任务完成，或确认它们能在升级后重新启动。
4. 重新运行安装脚本；指定版本时使用 `--version`。
5. 执行 `anytty --version`、`anytty config validate` 和 `anytty daemon doctor`。
6. 重启 daemon，再逐个测试 Local 和远程 endpoint。

安装新二进制不会自动证明旧 daemon 已经换成新版本，因此升级后应显式执行：

```sh
anytty daemon restart
anytty daemon status
```

## 降级与迁移

Beta 版本之间不保证可降级。尤其是配置 schema、endpoint registry、终端历史格式或凭据存储发生变化时，旧版本可能拒绝新数据。需要回退时，应使用升级前备份，并先在非生产设备验证。

迁移到另一台机器时，不要直接复制设备私钥或平台保护存储。安装新的 daemon 后重新配对客户端。普通 TUI 偏好可以单独迁移，但 endpoint credentials 和 grant 应按安全材料处理。

## 卸载

先停止当前用户 daemon：

```sh
anytty daemon stop
anytty daemon status
```

然后删除安装目录中的 `anytty` 可执行文件，并撤销安装脚本添加的 `PATH` 条目。是否删除配置、日志和历史应单独决定；用 `anytty config paths` 找到准确位置后再操作。

> 删除 history 或 credential 数据不可恢复。确认不再需要终端历史，并已经从 daemon 撤销遗留客户端 grant 后，再清理对应目录。

## 从源码构建

CLI/TUI 构建需要 Go 1.26.5；共享 UI 与移动端需要 Node.js 24 和仓库 lockfile。Android 额外需要 Java 21 与 Android SDK，iOS 需要 macOS 和完整 Xcode。

```sh
git clone https://github.com/anytty/anytty.git
cd anytty
npm ci
make build
make test
make test-clients
npm run public:check
```

构建产物位于 `.artifacts/bin/anytty`。开发构建不会自动替换系统中已经安装的 Release 二进制。

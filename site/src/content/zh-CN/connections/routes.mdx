# 多路径与连接诊断

同一设备可以同时保存 Direct、SSH 和 Cloud 路线。自动选择能减少手动切换，但排障时应先单独验证每条路线。

## 查看与测试

```sh
anytty endpoint show workstation
anytty endpoint policy show workstation
anytty endpoint test workstation --route ROUTE_ID --json
```

使用真实 route ID，逐条记录成功或错误。endpoint 列表只显示已登记信息；test 才会尝试路线并验证 AnyTTY 协议可达性。

## 设置下次连接策略

```sh
anytty endpoint policy set workstation --route auto
```

路线策略支持 `auto`、`direct`、`ssh`、`cloud`。Cloud 内部路径支持 `auto`、`p2p`、`relay`、`smart_route`；Relay 传输可选 `auto`、`udp`、`tcp`。参数存在不代表当前服务方案必定开放相应能力。

策略作用于下次会话；保存后重新连接并查看实际路线。强制某一路线适合诊断，恢复自动前先确认备用路径也能用。

## 按层排查

| 现象 | 先检查 |
| --- | --- |
| 超时或拒绝连接 | 目标是否运行、监听、网络和防火墙 |
| SSH 认证失败 | SSH 账号、密钥与主机验证 |
| daemon 身份不符 | 是否连接错误设备、设备是否重装或身份变化 |
| 授权失败 | 邀请是否兑换、grant 是否过期或撤销 |
| 连接成功但任务缺失 | endpoint 是否正确、筛选条件与 terminal ID |

自动回退只更换网络路径，不能绕过身份或授权失败。报告故障时记录客户端和 daemon 版本、时间、路线类型及脱敏错误；不要附上完整配对邀请或凭据。

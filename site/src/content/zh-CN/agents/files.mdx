# 远端文件与结果交付

Agent 的交付物不应只有“命令已经执行”。把输入、执行记录和产物路径连起来，用户才能审核和复用结果。

## 输入准备

先用 file stat / list 核对目标目录。需要上传配置或数据时，明确本地源文件和远端目标：

```sh
anytty file upload workstation ./input.json /srv/project/input.json --json
```

检查返回结果后再启动依赖该文件的任务。配置可能包含秘密，优先使用项目既有的安全配置方式，不要为了调试把完整内容打印进终端历史。

## 输出约定

要求任务写入明确路径，例如 `/srv/project/results/run-001/report.json`。真实项目中使用每次运行独立目录，避免新任务覆盖旧报告。任务结束后检查 exit_code，再 stat 文件确认存在与大小。

## 下载和验证

```sh
anytty file download workstation \
  /srv/project/results/run-001/report.json ./report.json --json
```

下载校验说明文件传输完整，不代表报告内容符合业务要求。JSON 报告还应解析检查，测试报告应对照失败数，构建产物应按项目规则检查。

App 可以用文件预览快速查看支持的文本或图片；预览被截断时不能替代完整验证。

## 建议的交付格式

| 信息 | 示例 |
| --- | --- |
| 执行位置 | workstation，/srv/project |
| 可复查任务 | create 返回的 target |
| 结果 | exited，exit_code 0；说明具体检查 |
| 远端产物 | /srv/project/results/run-001/report.json |
| 本地产物 | 下载后实际路径 |
| 未完成事项 | 失败原因、仍运行的服务或需人工检查内容 |

本机交付链接应指向真正下载的文件，不把远端路径伪装成本机可点击文件。清理远端产物前确认后续不再需要。

# 传输、预览与限制

传输用于取得完整文件，预览用于快速判断内容。两者的大小限制、显示方式和成功证据不同。

## 完整传输

CLI 上传等待 daemon 校验确认，下载也执行校验。App 在传输列表中显示结果。只有操作完成并通过相应校验，才适合继续消费产物；失败时保留错误，核对源路径与目标路径后再重试。

覆盖已有文件需要明确选择。脚本建议使用每次任务独立的结果目录，避免多个任务同时写同名产物。

## 原生 App 预览限制

| 项目 | 当前行为 |
| --- | --- |
| 源文件大小 | 预览入口限制为最多 64 MiB |
| 请求的预览载荷 | 最多 4 MiB，文本可能截断 |
| 图片尺寸 | 预览请求使用 2048 像素的尺寸约束 |
| 常见文本 | text、JSON、XML、YAML 等受支持 MIME |
| 常见图片 | PNG、JPEG、GIF、WebP、BMP |
| 渲染文本视图 | 支持格式且内容未截断时才适用 |

这些是当前原生预览实现的边界，不应当成文件上传下载统一的大小上限。图片载荷必须完整，不能拿一段截断图片当作成功预览。

## 不支持或过大时

下载文件后使用合适的本地应用打开，或者在远端生成较小的文本摘要、缩略图。不要只因文件扩展名存在，就承诺 Office、PDF、音视频或 3D 的原生预览。

## 交付结果

至少记录 endpoint、远端路径、本地路径和传输结果。对于构建产物，还需记录产生它的任务及退出状态；“下载成功”只证明传输了文件，不证明构建成功。完整流程见<DocLink locale="zh-CN" path="agents/files">Agent 文件交付</DocLink>。
